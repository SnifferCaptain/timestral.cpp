# 3rd Third-Party Headers

This directory holds the third-party headers of the optional backends, included only by timestral/eigen/ and timestral/ytensor/ once the matching CMake option is enabled. The default build (no optional backend) references nothing in this directory and still depends only on the C++17 standard library.

## ytensor.hpp

Source: single-header/ytensor_single.hpp from the main branch of [SnifferCaptain/ytensor](<https://github.com/SnifferCaptain/ytensor>), renamed to [ytensor.hpp](<ytensor.hpp>) after download. The file was generated by that repository's packer.py on 2026-07-31, version 0.14, with the file header signed SnifferCaptain.

License facts: the main branch of that repository has no license file at its root (LICENSE, LICENSE.md, LICENSE.txt and COPYING were all checked on 2026-10-21 and all return 404); the bfloat16 subcomponent inside the file states it is copied from openvino and is Apache-2.0 (Intel Corporation). This repository vendored the file on instruction, declares no license for it, and this does not change the licensing status of the rest of this repository.

The header uses C++20 concepts, so when the ytensor backend is enabled only timestral/ytensor/model.cpp compiles as C++20 (CMake sets this per source file; all other sources and tests stay C++17); the reference and Eigen backends stay C++17.

Matrix-multiplication backend facts (version 0.14, generated 2026-07-31):

- The header ships three matmul backends: YBLAS (its own AVX2 implementation), Eigen (strided mapping) and Naive (built-in loops); the default follows the `defaultMatmulBackend` priority YBLAS > Eigen > Naive and is chosen automatically.
- `YT_USE_EIGEN` is auto-defined by `__has_include(<Eigen/Core>)`: with this repository's 3rd/eigen on the include path, the ytensor backend actually takes the Eigen strided path by default; removing Eigen falls back to Naive. When the ytensor backend is enabled this project does not define the `YT_USE_EIGEN`/`YT_USE_YBLAS` feature macros, keeping the auto-detection logic exactly as downloaded.
- The YBLAS code block uses GCC-style `__attribute__((always_inline))` and requires AVX2+FMA (otherwise it triggers its own `#error`); under MSVC 19.36 it needs matching adaptations before it compiles: this project supplies the `__FMA__` macro (MSVC's /arch:AVX2 does not define it) before and after including this header in timestral/ytensor/model.cpp and empties out `__attribute__(x)`, adding /arch:AVX2 for that source file only; the repository's FP32 model does not use low-precision types, so these changes do not affect numeric semantics.
- The io part of the header unconditionally `#include <zlib.h>`; see the zlib entry below.

## zlib.h and zconf.h

The io part of ytensor unconditionally includes `<zlib.h>`, which MSVC and the Windows SDK do not provide, so a copy of the standard zlib 1.2.13 headers was vendored (zconf.h is the required companion of zlib.h). Both are declaration headers; this project calls no zlib functions and has no link dependency. They are byte-for-byte copies of the local standard zlib 1.2.13 source (E:\opencv\opencv\sources\3rdparty\zlib), with CRLF kept as upstream. License: the zlib license (full text in the [zlib.h](<zlib.h>) file header, Copyright 1995-2022 Jean-loup Gailly and Mark Adler).

## eigen/

Source: the fixed 3.4.0 release archive of [libeigen/eigen](<https://gitlab.com/libeigen/eigen>); only the eigen/ header directory from the archive is kept, with no tests, docs or other modules. Eigen as a whole is MPL-2.0; full text in [COPYING.MPL2](<eigen/COPYING.MPL2>). The other COPYING.* files are licenses of third-party solver interfaces shipped in the archive (SPQR, SuperLU, etc.); this project uses only the Dense linear-algebra headers and does not link those solvers.

Both sources can be re-downloaded from the pinned URLs above. The build does not download automatically. Files in this directory stay byte-identical to upstream except for the changes listed below (ytensor renamed by convention); the byte-level rules of style.md do not apply to unmodified content in this directory.

MSVC/OpenMP compatibility changes to ytensor.hpp (all minimal, affecting only the MSVC or GCC/Clang discrimination branches, no numeric code changed):

- The five groups of `#pragma omp declare reduction` (bfloat16/float16/float8 types) had their `#ifdef _OPENMP` guards changed to `#if defined(_OPENMP) && (defined(__GNUC__) || defined(__clang__))`: MSVC's OpenMP implementation does not accept declare reduction.
- Seven `#pragma omp ... proc_bind(...)` occurrences drop the proc_bind clause under `#if defined(_MSC_VER)` (MSVC's OpenMP does not support the clause; it is a thread-affinity hint, and removing it does not affect numerics or behavior on other platforms).
