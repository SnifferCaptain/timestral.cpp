# GPU后端取舍

## 当前决定

当前完整GPU模型后端只保留Vulkan。OpenGL与OpenCL均为❌，按用户要求删除，不再作为可选组件或未来迁移承诺。历史上做过算子实验不等于已经交付完整后端；过去的观察保留在本文，不将其改写成当前支持。

## 为什么不属于小幅迁移

| 项目 | OpenGL旧组件 | OpenCL旧组件 |
| --- | --- | --- |
| 实测边界 | Windows WGL、九个基础核及部分常驻链 | 四个独立OpenCL C 1.2算子，未验收保存的常驻执行器 |
| 当前共享模型缺口 | 没有attentionFused，与现有模型dispatch契约不完整 | 同样缺少attentionFused及后续常驻核，保存稿工厂未接入构建 |
| 执行环境 | OpenGL4.5目标/SPIR-V1.0，UBO/SSBO和上下文绑定，不是Vulkan目标二进制 | Kernel执行环境与Vulkan Shader执行环境不同，不能直接复用GLSL生成的Vulkan SPIR-V |
| 驱动事实 | 仅AMD WGL路径有旧实验，未交付Linux/EGL或完整5M模型验收 | 当时两设备IL版本字符串均为空；AMD创建队列失败，不能仅因loader存在IL入口就声称可移植 |
| 仍需工作 | 新关键核、平台上下文、资源/同步适配和完整模型/缓存/分位数数值及性能验收 | 新关键核、编译/IL路径、资源/同步/驱动问题和同等完整验收 |

共享Transformer和部分算子数学可以复用，但不能只换API名称或一组shader编译参数就得到完整后端。改回分离attention算子以躲避缺口、CPU静默回退或只跑四算子后宣称整模型支持，都不作为交付方案。

## 已删除的范围

- 两个实验组件目录的全部host、loader、执行器、工厂保存稿、shader/嵌入核、目录文档与CMake
- 两个专用算子测试，未触动其它后端测试或冻结预算
- 根构建的两个可选组件入口与OpenCL实验执行器入口
- Linux工作流中的OpenCL静态组件构建任务
- 正式文档中指向已删除组件的链接和启用说明

未创建另一套正式“实验后端”目录，也不保留空工厂或伪实现。旧构建缓存显式开启已移除选项时会配置失败，提示使用Vulkan，不静默忽略旧选项并让用户误以为仍选中了该API。

Vulkan及共享GPU契约、CPU四后端、原始模型/测量数据不删除。性能图不因组件取舍而重填数据。当前支持矩阵见[主说明](<../../README_zh.md#平台与后端矩阵>)，现有GPU的已知数值压力失败仍见本地数值记录。
